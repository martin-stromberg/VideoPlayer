# Release Notes

## Important Notes Before Update

- TV-Sender youth-protection windows: the schedule now respects age-appropriate air times — rated material may only start inside its configured local window (defaults: 12+ from 20:00, 16+ from 22:00, 18+ from 23:00 until the shared 06:00 night end; MPAA ratings map onto the same windows via their normalized minimum age). Four time fields under `Einrichtung → TV-Sender` („Altersgerechte Sendezeiten (Jugendschutz)", „Einstellungen" tab, group „Planung") adjust the schema; material **without** a rating — including clips, trailers and fillers — only airs inside the FSK-18 night window unless the new „Material ohne Altersfreigabe" selector is switched from the default „Wie ‚ab 18 Jahre' behandeln (nur nachts planbar)" to „Jederzeit planbar" (the live-stream standby clip is exempt). A started broadcast always runs to its end; series and playlists keep their air order (a blocked head waits), while unordered rings skip blocked titles and offer them again on the next lap. The „Planbar" diagnosis now names „{n} nicht altersgerecht im Sendefenster" / „kein altersgerechtes Material im Fenster" as reasons. **Update note:** already scheduled slots that violate the delivered default schema are displaced and re-planned on the next evaluation — daytime gaps may remain while clips/trailers/fillers are restricted to the night window; new columns `Setups.ProgramScheduleAgeWindow*Local`/`ProgramScheduleUnknownRatingMode` (migration `AddProgramScheduleAgeWindows`, applied automatically; older backups restore the delivered schema and the restrictive mode) (Issue #271). See `docs/help/tv-sender.md`.
- Media sources can now be hidden from the navigation menu: the source details page (`Einrichtung → Quellen → Quelle bearbeiten`) carries a new „Im Menü ausblenden" checkbox meant for pure clip/filler sources (e.g. sources that only supply placeholder clips for the TV channel). Hiding a source removes its menu entry for administrators and regular users alike while leaving everything else untouched — access grants, scanning, filler rules, clip groups and the direct link to the source page all keep working (new non-nullable column `MediaSources.HiddenInMenu`, migration `AddMediaSourceHiddenInMenu`, applied automatically; backups from older versions restore the flag as `false` = visible because the column is optional during restore). The flag is also exposed on `DtoMediaSource` (`GET /api/Sources`), so external clients can apply the same filtering. See `docs/help/medienquellen/einrichtung-anwender.md`.
- Seasonal home lists API: deploy this server release before rolling out a mobile app version that requests `GET /api/home/seasonal-genres`. The web home page also uses this authenticated endpoint.
- Age ratings (FSK & MPAA) are now captured for movies and TV shows: the scan reads `<mpaa>` (primary) and `<certification>` (fallback) from the NFO files (`<name>.nfo`/`movie.nfo`, `tvshow.nfo`), normalizes raw values like „FSK 12", „Rated PG-13" or „Germany:16" onto known levels (FSK 0/6/12/16/18, MPAA G/PG/PG-13/R/NC-17) and stores the raw value plus a comparable minimum age (new nullable columns `Movies.AgeRating*`/`TVShows.AgeRating*`, migration `AddAgeRatings`, applied automatically; backups from older versions restore fine because the columns are optional during restore). The rating shows as a badge in the detail views — seasons and episodes inherit the show's rating — and is editable in the admin edit mode via a dropdown. When the NFO carries no rating an optional, fault-tolerant TMDB lookup can fill it (new `Tmdb` configuration section, disabled by default; the API key lives outside the repository, see `docs/SECRETS_MANAGEMENT.md`); without configuration the field simply stays empty. A one-time backfill on startup supplies the existing library, and manually edited entries are never overwritten. See `docs/help/medienquellen/beschreibung.md` and `docs/help/medien-editiermodus.md`.
- TV-Sender clip groups: placeholder clips can now be managed in named groups (new tables `ProgramClipGroups`, `ProgramClipGroupItems`, `ProgramRuleClipGroups`) — the new „Clip-Gruppen" tab on the TV-Sender administration page creates, renames and deletes groups and assigns or removes member clips (unclassified video files only, i.e. files without a movie/episode link; a file classified later drops out of rotation automatically). In the rule editor a non-filler rule with a slot duration selects any number of groups plus a per-rule grace period „Karenzzeit" (new non-nullable column `ProgramRules.PlaceholderGrace`, default 15 minutes): once the time left until the period end drops below the grace, no further title starts and the rest is shared evenly across clips of the assigned groups — before the first title, between titles and after the last, round-robin over the groups (the last clip may overshoot the period end; clips never reach into occupied or reserved higher-priority windows). A reserved system group „Trailer“ — seeded with Id 1 by migration `AddProgramClipGroups` (applied automatically), not editable and its name reserved for user groups too — supplies trailers whose movie airs within `ProgramSchedule:TrailerLeadDays`, so a trailer clip slot shows its movie in the program guide. Rules without any clip group behave exactly as before. Backups from older versions restore fine: the new tables and the column are optional during restore, and a missing `PlaceholderGrace` column is injected with the 15-minute default. See `docs/help/tv-sender.md`.
- Robustness fix with a data cleanup: the `Setups` settings row could be created twice under a startup race (the data upgrade, the first request and test seeds each created it check-then-act on an empty read), and `FirstOrDefault` then read either of the two rows — flags like `TvSenderEnabled` could flip between requests. Migration `AddSetupsSingleRowIndex` (applied automatically) merges duplicate rows — the oldest row wins — and adds a unique index over a constant expression so the table can never hold more than one row again; row creation now funnels through a single ordered path, and a losing insert re-reads the winner row. No action needed; should a database ever have carried two differing rows, the surviving settings are those of the older row.
- TV-Sender release switch: the automated TV channel is now off by default and must be explicitly released by an administrator via „Einrichtung → Allgemein → Automatisierten TV-Sender freischalten" (new column `Setups.TvSenderEnabled`, migration `AddSetupTvSenderEnabled`, applied automatically; restores default to `false`). While unreleased, the „Live-TV" navigation entry is hidden, `/live-tv` and `/admin/tv-sender` show a hint, `/api/program-guide/*` and `/api/live-stream/*` answer 404, and the schedule/segmentation/duration-probe workers idle. **Update note:** previously installed instances keep the sender *disabled* until released — enable it once under „Allgemein". Also in this change: genre-rule strand order is now a deterministic hash mix per rule instead of alphabetical (no more permanent „A"-show lead), and the Live-TV „Die nächsten Stunden" list keeps refreshing even when the now/next endpoint is down (poll starts only on the interactive instance — no prerender timer leak). See `docs/help/tv-sender.md`.
- TV-Sender rule features: genre rules with several series now interleave the shows inside their window instead of stripping one series per day — each show keeps its slot position across days and continues its own episode order, with an independent persisted continuation cursor per series (new nullable column `ProgramRuleCursors.StrandKey`, migration `AddProgramRuleCursorStrandKey`, applied automatically; backups from older versions restore fine because the column is optional during restore and restores to `null` = single rule cursor as before). Two new recurrence modes join the rule editor — „Werktags (Mo–Fr)" and „Wochenende (Sa+So)" — and the rule editor opens as an overlay panel above the rule list again, closable via the dimmed background like the other dialogs. See `docs/help/tv-sender.md`.
- The automated TV channel now recognizes trailer files during the media scan following the Plex/Jellyfin convention — a file with a `-trailer` suffix next to the movie (`Film.mp4` → `Film-trailer.mp4`) and every video inside a `trailers/` subfolder of a movie directory. Detected trailers are linked to their movie (new column `MovieMediaItems.IsTrailer`, migration `AddMovieMediaItemIsTrailer`, applied automatically; backups from older versions restore fine because the column is optional during restore and defaults to `false`), get their duration probed like every other video, and never appear as a regular movie in the program or media views. A new material "Trailer anstehender Filme" (trailer of upcoming movies) for filler rules makes the schedule prefer trailers whose movie airs within the configurable lead window `ProgramSchedule:TrailerLeadDays` (default: 7 days); where no upcoming trailer fits, the remaining filler rules cover the gap as before. In the program guide a trailer slot shows the name of its movie. See `docs/help/tv-sender.md`.
- The UDP broadcast discovery answer (`VIDEOWEBPLAYER_SERVER:<url>` on port 5001) now reports the server's reachable public base URL **including scheme, host, port and path** (e.g. `https://videos.example.com/videoplayer/`) instead of the previously hard-coded `http://{Host:Address ?? "localhost"}:{Host:Port ?? "5000"}` — the default no longer reports an unusable `localhost` address but derives the host's LAN IPv4 address and bound port; clients that parse the answer must tolerate a path component (the MAUI app adjustment is a follow-up in the app repository). The reported URL is resolved per request in this order: the new admin field "Öffentliche Basis-URL" under `Einrichtung` → `Allgemein` (persisted in the new nullable `Setups.DiscoveryPublicBaseUrl` column, applied automatically by the new migration `AddSetupDiscoveryPublicBaseUrl` on startup; backups from older versions restore it as unset because the column is optional during restore) → the new optional configuration `Discovery:PublicBaseUrl` (merge-protected via `AutoUpdate:ProtectedFiles`; an invalid value fails startup) → automatic derivation from bound server addresses, `Kestrel:Endpoints`, `Host:Address`/`Host:Port` and the host's LAN address — loopback/wildcard addresses are never reported, and a loopback-style `Host:Address` is now ignored instead of reported. Under IIS `OutOfProcess`, behind a reverse proxy or with TLS termination the derivation only sees the internal backend — an explicit URL (admin field or `Discovery:PublicBaseUrl`) is required there.
- The server now announces itself via mDNS/DNS-SD (service type `_videowebplayer._tcp.local.`, UDP port 5353) so client apps can find it automatically. A new optional `Mdns` section was added to `appsettings.json` (`Enabled`, `InstanceName`, `ServiceType`, `Port` — all keys are merge-protected via `AutoUpdate:ProtectedFiles`, so local adjustments survive updates). The advertisement is active only when both `Mdns:Enabled` (default `true`, operator master switch) and the new admin switch "Server per mDNS im Netzwerk ankündigen" under `Einrichtung` → `Allgemein` (default on) are set. Firewall: UDP 5353 must be open (multicast 224.0.0.251). Under IIS `OutOfProcess` the bound address is the internal backend port — set `Mdns:Port` to the site port there. On a Linux host that already publishes a static Avahi service for this server (`docs/INSTALL_AVAHI.md`), remove that service file or set `Mdns:Enabled=false` to avoid double advertisement. The UDP broadcast fallback on port 5001 is unchanged. **Breaking for discovery clients:** clients and integrations that previously searched for the server under `_http._tcp.local.` must switch to `_videowebplayer._tcp.local.` — the server deliberately does not announce itself under the generic type in parallel (the service type itself is configurable via `Mdns:ServiceType`). The MAUI app will be switched to the dedicated service type in the app repository; until then it finds the server via the UDP fallback.
- Update installations under IIS now work without elevated rights: the updater detects the IIS hosting model itself (out-of-process and in-process), takes the site offline via `app_offline.htm`, replaces the files and lets IIS restart the application on the next request — no extra configuration is needed. A configured `AutoUpdate:ServiceName` or `AutoUpdate:ExecutablePath` is ignored under IIS (with a log warning); the service-name field in the update settings is disabled and a persisted value is cleaned up. Only set `AutoUpdate:AppPoolName`/`SiteName` if the privileged variant is deliberately wanted (requires the application pool identity to hold IIS management rights). Note for in-process hosting: the update terminates the pool's `w3wp` and therefore requires a dedicated application pool per application. Diagnostics: all Windows install scripts log every step to `Updates/update.log` and archive a copy of the executed script as `update-failed.ps1` on failure; the scripts run as a detached process (WMI `Win32_Process.Create`) — if the application identity may not call `Create` in a hardened environment, the installation fails with `InstallationFailed` instead of silently failing. See [martin-stromberg/msTools.Updater#69](https://github.com/martin-stromberg/msTools.Updater/issues/69) and [#70](https://github.com/martin-stromberg/msTools.Updater/issues/70).
- Fixed: update installations no longer blindly replace deployment-side file customizations. The shipped `AutoUpdate:ProtectedFiles` list protects `web.config` and `appsettings*.json`: the generated installation script backs matching files up to `Updates/backup/` before copying the package and then merges the configured XML elements/attributes (`<environmentVariables>`, `security/ipSecurity`, `httpProtocol`, deployment-side `aspNetCore` attributes) and listed JSON keys from the existing file into the package version — package-side improvements to the same files keep arriving. **Migration note:** the protection only takes effect with the first update **after** this release, because the update to this version still runs with the old version's script — existing installations must re-apply their `web.config`/`appsettings` customizations once after updating to this version. On Linux, the `Merge` strategy requires `python3` on the target system (otherwise merges are skipped with a log entry and the file backups remain in `Updates/backup/`). Storing secrets as machine-wide environment variables (`Jwt__*`) remains the recommended variant; the optional, never packaged `appsettings.Local.json` in the application directory covers arbitrary deployment-side overrides outside the `JsonKeys` list. See `docs/Anforderung_msTools_Updater_Dateierhalt.md` and [martin-stromberg/msTools.Updater#66](https://github.com/martin-stromberg/msTools.Updater/issues/66).
- The media endpoints (`GET /api/items/{type}/{id}`, `.../stream`, `.../download`) now answer with the status code that matches the situation: `403 Forbidden` instead of `401 Unauthorized` when a signed-in user has no unlock for the title, and `404 Not Found` instead of `500 Internal Server Error` for an unknown type or id and for a title without a video file. `401` now only means that the credential is missing or invalid. Saving metadata (`POST /api/items/metadata`) follows the same rule: a signed-in non-administrator is refused with `403` instead of `401`. Downloading also accepts the type `tvshow` now, exactly like streaming does. Integrations that treated a `401` from these endpoints as “no access” must now check for `403`, and a client that renews its session on `401` must not do so on `403` or `404` — both are final. See `docs/API.md`.
- New database migrations add the playlist tables (`Playlists`, `PlaylistEntries`, `PlaylistEntryExclusions`, `PlaylistGenres`), playlist cover fields and the `IsPublic` flag on `Playlists`/`Pictures` a `PlaylistId` column on `ContinueWatchingEntries`, the `PlaylistBackfillMarkers` table and an index on `PlaylistEntries(MediaType, MediaId)` for the automatic backfill of new content, and a `PlaylistBackfillLastSweepAt` column on `Setups`; they are applied automatically on startup. Backups from older versions remain restorable because the new tables and columns are optional during restore.
- A new optional `Playlists` section was added to `appsettings.json` (limits for playlists/entries, paging sizes, backfill block size, block pause, settle time and interval of the daily safety sweep, allowed cover upload formats and size, generated cover dimensions and JPEG quality); the defaults apply automatically if the section is absent.
- Automatically generated playlist covers are not exported to backups (like other generated pictures); after a restore such playlists show the placeholder image until the cover is regenerated manually. Uploaded covers are included in backups.
- Backup upload API changed: the multipart endpoint `POST admin/backups/api/upload` was replaced by a chunked `application/octet-stream` protocol (`POST admin/backups/api/upload/chunk`, `GET`/`DELETE admin/backups/api/upload/{id}`) — custom scripts or integrations using the old endpoint must be updated.
- New configuration `Kestrel:Limits:MaxRequestBodySize` in `appsettings.Production.json` is set to `0` (unlimited) and applied via an explicit `ConfigureKestrel` binding, because Kestrel does not load `Limits` from configuration on its own.
- IIS deployments: the hosting model is now `OutOfProcess` (`AspNetCoreHostingModel` in the project file); the IIS `requestFiltering` limit `maxAllowedContentLength` (~30 MB default) must be raised so large uploads are not blocked.
- The configurable upload limit `Backups:MaxUploadSizeBytes` (default 5 GiB) is now enforced server-side — files above the limit are rejected; raise it in the admin UI if larger backups must be accepted.
- The database schema changed (`PairingCodes` gained `Kind`/`TicketHash`, new `RefreshTokens` table). After updating, run `dotnet ef database update` (or apply the new migration `AddPairingBootstrapAndRefreshTokens` via your usual migration step) before starting the app.
- New optional configuration keys: `Pairing:BootstrapTicketTtlMinutes` (default 5), `Pairing:BootstrapMaxTicketsPerHour` (default 10), `Pairing:BootstrapAdminOnly` (default `false`), `Auth:RefreshTokenTtlDays` (default 30).
- Backups from older versions remain restorable across the device pairing change as well: the tables `PairedDevices`, `PairingCodes` and `RefreshTokens` and the columns `Kind`/`TicketHash` on `PairingCodes` are optional during restore. Such a backup contains no paired devices and no sessions, so after restoring it these tables are empty — the device list is empty, previously paired devices and client apps are signed out and must be paired again, and pending pairing codes and bootstrap tickets do not come back. A backup of the current version still contains all three tables and restores their content completely.
- The image processing library was switched from `SixLabors.ImageSharp` to `SkiaSharp` (MIT licence): ImageSharp 4.x requires a paid Six Labors licence in release builds, and the currently used version 3.1.11 carries five security advisories (two of them high severity and reachable through uploaded cover images). Behaviour is unchanged; playlist cover validation additionally got a structural PNG integrity check because SkiaSharp's PNG decoder tolerates truncated files.

## What's New

- TV channel schedule, fixed: repeated re-evaluations no longer pile up series of „verdrängt" copies of the same broadcast ahead of its „geplant" entry. Three stability defects combined: once the duration probe measured a second file linked to the same content, the schedule preferred the newly probed file and judged every slot still referencing the old one invalid — each probe batch displaced and re-materialized the same broadcast again; the slot check now accepts any file still linked to the content with a known runtime (the slot length must match the stored file's own runtime), so only an unlinked/deleted file or a genuinely different length still displaces. Seasonal/hidden genre resolution also ran off the wall clock instead of the run's own time base and could invalidate a broadcast without any input change — the expansion now uses the run's `coverageStart` end to end. And a broadcast legitimately shifted behind another became unprovable once the occupying slot was itself displaced, oscillating between shift and displacement run over run — the re-evaluation now reads the displaced history of its load window as shift evidence (evidence only, never as coverage; „Verdrängte bereinigen" removes that evidence, so an affected broadcast may be displaced and re-planned once after a cleanup). Signalling calmed at the same time: the duration-probe worker bundles its per-batch wake-ups into a single wake per probe pass, and a scan-style run now wakes the schedule worker only when it actually suppressed a change notification — idle passes no longer trigger empty re-evaluations. Existing displaced rows stay as history; no data cleanup is needed (Issue #290). See `docs/help/tv-sender.md`.
- TV channel schedule, fixed: unordered material rings (movie collections, genre movie strands, clip sources and clip groups) no longer start every rule at the alphabetically/oldest-release first title — the observed bias toward titles starting with „A“. The rings are now mixed deterministically per rule and strand (FNV-1a hash over rule id, strand and content), so head picks distribute across the material while remaining reproducible for the schedule cursors and the re-evaluation; series episodes, playlists and the airings-ordered trailer ring keep their intentional order. **Update note:** on the first schedule re-evaluation after the update a few broadcasts created under the old sort order may be judged not reproducible and be re-planned once via their cursor — a one-time, intended effect (Issue #297). See `docs/help/tv-sender.md`.
- TV-Sender schedule view: gapless runs of placeholder clips (the clip-group grace fill) now collapse into a single compact „Platzhalter-Clips" block card in the admin „Sendeplan" tab — showing the time range, clip count and total duration instead of one card per short clip. An icon button („Platzhalter-Clips anzeigen") opens an overlay listing every clip in air order with start time, duration and title. Single clips stay regular cards; runs broken by other broadcasts, a rule change or a time gap stay separate blocks, and displaced clips remain single cards. The grouping is display-only — scheduling and air order are unchanged, and the program guide / Live-TV page still lists every clip individually. Technically the slots are marked at creation time via the new non-nullable column `ProgramSlots.IsClipFill` (migration `AddProgramSlotIsClipFill`, applied automatically; backups from older versions restore the flag as `false` because the column is optional during restore — pre-existing clip-fill slots simply keep showing as single cards until they roll out of the schedule window). See `docs/help/tv-sender.md`.
- TV-Sender: new admin setting „Inhaltsspektrum" (content spectrum) in the „Einstellungen" tab (group „Planung") — two options: „Nur für alle Benutzer freigegebene Inhalte" (default, the previous behaviour) and „Alle Inhalte, die sich aus den Regeln ergeben", which lifts the audience-release check of the schedule planning for every expansion path (movies, episodes, clip-source filler, clip groups and trailers). **Attention:** in the second mode viewers can see stream contents they may not access in the media library — the UI states this consequence next to the setting. The change takes effect on the next planning run (saving wakes the schedule worker immediately); switching back displaces the no-longer-permitted slots on the next re-evaluation. Persisted as new column `Setups.ProgramScheduleContentScope` (migration `AddSetupProgramScheduleContentScope`, applied automatically; backups from older versions restore `SharedOnly` = the restrictive default because the column is optional during restore). See `docs/help/tv-sender.md`.
- TV-Sender schedule, fixed: placeholder clips of a slot-duration rule were distributed against a wrongly computed period end whenever the written airing did not begin at the nominal occurrence start (e.g. a plan run in the middle of an ongoing period, or a start shifted behind an overshooting predecessor) — clip blocks could be scheduled hours past the real period end, and re-positioned titles could reach into occupied or reserved windows of other rules, producing overlapping send times. The clip fill now derives the period end from the occurrence start, places the re-laid titles and clips only inside the free room before the next occupied or reserved boundary, and never starts a placeholder block after the period end; a started clip may still overshoot the period end. See `docs/help/tv-sender.md` (Issue #291).
- TV-Sender: new standby stream for the warm-up phase — as long as no real `live.m3u8` with a segment exists yet (e.g. after a server start or update), the stream endpoint serves an in-memory transitional clip instead of `404`: by default the new embedded Funki clip „Gleich geht's los!", optionally an administratively configured unclassified clip (pre-segmented once via `ffmpeg`, cached under `Data/LiveStreamStandby/`); seamless transition via `#EXT-X-DISCONTINUITY`, and the last advertised standby segment stays reachable until the client has switched. See `docs/help/tv-sender.md`.
- TV-Sender administration: new „Standby-Clip (Überbrückung)" card in the „Einstellungen" tab with clip selection from the media sources (search, source filter, „Weitere laden"); `Setup.LiveStreamStandbyMediaItemId` holds the choice (migration `AddSetupLiveStreamStandbyMediaItem`, applied automatically), `null` = default clip. A selection takes effect with „Speichern" — an unsaved choice is flagged by the hint „Auswahl wird mit ‚Speichern' übernommen", and a deleted previous choice is shown as „Zuvor gewählter Clip ist nicht mehr vorhanden — Standard-Clip wird verwendet" and cleared on the next save.
- TV-Sender: when the live-stream background run starts, the segment directory is now emptied already before the internal start delay, so leftovers of a previous delivery can no longer be served during the warm-up phase.
- TV-Sender: all live-stream responses — playlists, real segments and standby deliveries — now carry `Cache-Control: no-store`.
- Seasonal home genre lists: the web home page now loads active, non-empty sections through the authenticated `GET /api/home/seasonal-genres` API also used by the mobile app. The response includes only media visible to the signed-in user and an exclusive UTC `expiresAt` for each season; the web page removes expired sections automatically while it remains open. Deploy this server before the companion app update. See [API documentation](api/seasonal-genres.md) and [user help](help/saisonale-startseitenlisten.md).
- TV-Sender: missing ffmpeg/ffprobe binaries can now be installed directly from the TV-Sender settings — the „ffprobe wurde nicht gefunden" warning in the „Laufzeitermittlung" tab and the „ffmpeg wurde nicht gefunden" warning on the segmentation card each carry a download button. A confirmation dialog first notes the GPL licence of the usual static ffmpeg builds; the download then fetches the static package matching the runtime platform (win-x64/linux-x64), extracts `ffmpeg` and `ffprobe` into `tools/ffmpeg/` next to the application — the convention directory both locators already search, which survives update overlays — and shows progress and understandable errors on the way. After the download the locators resolve the binaries without a restart, so the paused duration probe and live stream pick up on their next worker cycle. The action is administrator-only, enforced server-side, and a running download blocks further starts. The alternative paths `MediaProbe:FfprobePath`/`MediaProbe:FfmpegPath`, `tools/ffmpeg/` and `PATH` stay unchanged, and the download sources can be overridden via the new optional `MediaProbe:DownloadSources` configuration (defaults point to the static builds linked from ffmpeg.org). Implemented with the new `SharpCompress` package (MIT licence). See `docs/help/tv-sender.md`.
- TV-Sender live stream, fixed: expired HLS `.ts` segments could not be deleted under Windows while a viewer was still downloading them — the `FileShare.Read` handle opened internally by `PhysicalFile` blocked the delete, which could interrupt ffmpeg's rolling-window cleanup and the segment retention sweep. Segment delivery now opens the file allowing parallel writes and deletion (`FileShare.ReadWrite | FileShare.Delete`): an in-flight download runs to completion even after the file is already gone. Segment answers deliberately no longer carry `Last-Modified`/`ETag` validators — the segment names are unique and timestamped and their content never changes, so conditional requests never applied anyway (Issue #265). See `docs/help/tv-sender.md`.
- TV-Sender: the internal, token-secured media-stream endpoint `GET /api/internal/media-stream/{token}` now follows the global release switch `TvSenderEnabled` like every other TV-channel endpoint — while the feature is unreleased it answers 404 (checked before the token is resolved, so the feature stays indistinguishable from „does not exist"), even for requests carrying a still-valid token. The endpoint serves the ffprobe HTTP path of the duration probe and the ffmpeg input of the live-stream segmenter; with the feature switched off, new requests — among them the follow-up/range requests of a probing ffprobe and new connections — answer 404, and when the endpoint answers an ffmpeg call with 404 that exit is recorded as an HTTP transport failure, so the next segmenter start on the same slot falls back to `pipe:0` input — consistent with all other gates. See `docs/help/tv-sender.md`.
- TV channel schedule: broadcasts that began more than 24 hours ago are no longer displaced and re-planned on every schedule run. Previously the periodic re-evaluation proved each still-running airing only against its fixed 24-hour lookback window — a marathon block or a seamlessly chained run of a dense rule lost its originating occurrence from the window, was misjudged as unverifiable and displaced, then re-materialized and displaced again run over run. The re-evaluation now widens its lookback on demand — only when a slot provably reaches behind the window edge or the base validation leaves an airing unproven — up to the configurable maximum `ProgramSchedule:MaxOccurrenceLookbackDays` (default: 7 days, values ≤ 0 fall back to the default); merged chains are decomposed into their per-occurrence airings against strictly ascending occurrences. Airings whose real start is older than the configured bound stay unprovable and are still displaced and re-planned; changed, deactivated or deleted rules displace exactly as before. See `docs/help/tv-sender.md`.
- TV-Sender robustness fix: the continuation cursors of program rules are now deduplicated and protected against duplicates. SQLite treats `NULL` values as distinct inside a unique index, so the `(ProgramRuleId, StrandKey)` constraint never covered the single overall cursor of non-interleaved rules (`StrandKey = NULL`) — under rare conditions (parallel inserts, restores) several such rows could accumulate and the read paths picked an arbitrary one. A data migration now merges existing `NULL` duplicates per rule (the youngest row wins) and a new filtered unique index enforces one `NULL` row per rule on database level; all cursor lookups choose deterministically should duplicates ever appear again, and restoring a backup that still contains `NULL` duplicates deduplicates it instead of failing (migration `EnforceProgramRuleCursorNullStrandKeyUnique`, applied automatically).
- TV-Sender: broadcast times (`ProgramSlots.Start`/`End`) are now read back with an explicit UTC time-zone marker. They were always stored as UTC, but the database layer returned them without the marker — harmless for the schedule display itself, yet fragile for every kind-aware consumer. No schema or data change; existing schedules are unaffected.
- Failed duration probes can now be re-queued from the TV-Sender administration page: in the „Laufzeitermittlung" tab the expandable „Fehlgeschlagene Dateien" list offers an „Erneut ermitteln" action per file, and an „Alle zurücksetzen" button next to the failed counter (with confirmation dialog) resets the whole permanently-failed set — including entries beyond the displayed cap. A reset clears the attempt counter and last-attempt timestamp (the same reset the media scan applies to replaced files), so the probe picks the file up again on its next run — useful after a broken file was repaired or replaced without the scan noticing. Files that are still broken simply gather attempts again and reappear in the failed list after `MediaProbe:MaxAttempts`. The action is administrator-only, enforced server-side. ## Wichtige Hinweise vor dem Update

- TV-Sender-Jugendschutzfenster: Der Sendeplan berücksichtigt jetzt altersgerechte Sendezeiten — altersgeprüftes Material darf nur noch innerhalb seines konfigurierten lokalen Fensters starten (Standard: ab 12 ab 20:00, ab 16 ab 22:00, ab 18 ab 23:00 bis zum gemeinsamen Nachtende 06:00; MPAA-Freigaben wirken über ihr normalisiertes Mindestalter auf dieselben Fenster). Vier Zeitfelder unter `Einrichtung → TV-Sender` („Altersgerechte Sendezeiten (Jugendschutz)", Tab „Einstellungen", Gruppe „Planung") stellen das Schema ein; Material **ohne** Altersfreigabe — einschließlich Clips, Trailer und Füller — läuft nur noch im FSK-18-Nachtfenster, solange das neue Auswahlfeld „Material ohne Altersfreigabe" nicht vom Standard „Wie ‚ab 18 Jahre' behandeln (nur nachts planbar)" auf „Jederzeit planbar" umgestellt wird (der Standby-Clip des Live-Streams ist ausgenommen). Ein begonnener Beitrag läuft immer zu Ende; Serien und Playlists behalten ihre Sendereihenfolge (ein gesperrter Kopf wartet), ungeordnete Ringe überspringen gesperrte Titel und bieten sie auf der nächsten Runde erneut an. Die „Planbar"-Diagnose nennt jetzt „{n} nicht altersgerecht im Sendefenster" / „kein altersgerechtes Material im Fenster" als Gründe. **Update-Hinweis:** Bereits eingeplante Sendeplätze, die gegen das ausgelieferte Standard-Schema verstoßen, werden bei der nächsten Neubewertung verdrängt und neu geplant — Tageslücken können bestehen bleiben, solange Clips/Trailer/Füller auf das Nachtfenster beschränkt sind; neue Spalten `Setups.ProgramScheduleAgeWindow*Local`/`ProgramScheduleUnknownRatingMode` (Migration `AddProgramScheduleAgeWindows`, wird automatisch angewendet; Backups älterer Versionen restaurieren das ausgelieferte Schema und den restriktiven Modus) (Issue #271). Siehe `docs/help/tv-sender.md`.
- Medienquellen lassen sich jetzt aus dem Navigationsmenü ausblenden: Die Quellen-Detailseite (`Einrichtung → Quellen → Quelle bearbeiten`) trägt die neue Checkbox „Im Menü ausblenden" — gedacht für reine Clip-/Füller-Quellen (z. B. Quellen, die nur Platzhalter-Clips für den TV-Sender liefern). Eine ausgeblendete Quelle verliert ihren Menüeintrag für Administratoren und Anwender gleichermaßen, während alles Übrige unverändert bleibt — Freigaben, Scan, Füller-Regeln, Clip-Gruppen und der direkte Link auf die Quellseite funktionieren weiter (neue non-nullable Spalte `MediaSources.HiddenInMenu`, Migration `AddMediaSourceHiddenInMenu`, wird automatisch angewendet; Backups älterer Versionen restaurieren das Flag als `false` = sichtbar, weil die Spalte beim Restore optional ist). Das Flag liegt ebenfalls auf `DtoMediaSource` (`GET /api/Sources`), sodass externe Clients dieselbe Filterung anwenden können. Siehe `docs/help/medienquellen/einrichtung-anwender.md`.
- Saisonlisten-API: Diesen Serverstand bereitstellen, bevor eine mobile App-Version ausgerollt wird, die `GET /api/home/seasonal-genres` abruft. Auch die Webstartseite verwendet diesen authentifizierten Endpunkt.
- Altersfreigaben (FSK & MPAA) werden jetzt für Filme und Serien erfasst: Der Scan liest `<mpaa>` (primär) und `<certification>` (Fallback) aus den NFO-Dateien (`<name>.nfo`/`movie.nfo`, `tvshow.nfo`), normalisiert Rohwerte wie „FSK 12", „Rated PG-13" oder „Germany:16" auf bekannte Stufen (FSK 0/6/12/16/18, MPAA G/PG/PG-13/R/NC-17) und speichert den Rohwert plus ein vergleichbares Mindestalter (neue nullable Spalten `Movies.AgeRating*`/`TVShows.AgeRating*`, Migration `AddAgeRatings`, wird automatisch angewendet; Backups älterer Versionen bleiben wiederherstellbar, weil die Spalten beim Restore optional sind). Die Freigabe erscheint als Badge in den Detailansichten — Staffeln und Episoden erben die Freigabe der Serie — und ist im Admin-Editiermodus per Dropdown pflegbar. Trägt die NFO keine Freigabe, kann sie ein optionaler, fehlertoleranter TMDB-Lookup ergänzen (neuer Konfigurationsabschnitt `Tmdb`, standardmäßig deaktiviert; der API-Schlüssel liegt außerhalb des Repositorys, siehe `docs/SECRETS_MANAGEMENT.md`); ohne Konfiguration bleibt das Feld schlicht leer. Ein einmaliger Backfill beim Start versorgt den Bestand, und manuell bearbeitete Einträge werden nie überschrieben. Siehe `docs/help/medienquellen/beschreibung.md` und `docs/help/medien-editiermodus.md`.
- TV-Sender-Clip-Gruppen: Platzhalter-Clips lassen sich jetzt in benannten Gruppen verwalten (neue Tabellen `ProgramClipGroups`, `ProgramClipGroupItems`, `ProgramRuleClipGroups`) — der neue Tab „Clip-Gruppen" auf der TV-Sender-Verwaltungsseite legt Gruppen an, benennt sie um, löscht sie und ordnet Mitglieds-Clips zu bzw. entfernt sie (ausschließlich uneingeordnete Videodateien — ohne Film-/Episoden-Bezug; eine später eingeordnete Datei fällt automatisch aus der Rotation). Im Regel-Editor wählt eine Regel, deren Regelart nicht „Platzhalter/Füller" ist und die eine Sendeplatz-Länge trägt, beliebig viele Gruppen sowie eine regel-eigene Karenzzeit (neue non-nullable Spalte `ProgramRules.PlaceholderGrace`, Standard 15 Minuten): Bleibt bis zum Periodenende weniger als die Karenzzeit frei, startet kein weiterer Titel und die Restzeit wird gleichmäßig auf Clips der zugeordneten Gruppen verteilt — vor dem ersten Titel, zwischen den Titeln und nach dem letzten, im Wechsel über die Gruppen (der letzte Clip darf über das Periodenende ragen; in belegte oder reservierte Fenster höherpriorer Regeln ragen Clips nie). Die reservierte System-Gruppe „Trailer" — per Migration `AddProgramClipGroups` mit Id 1 angelegt (wird automatisch angewendet), nicht bearbeitbar, ihr Name auch für eigene Gruppen reserviert — liefert Trailer, deren Film innerhalb des Vorlaufs `ProgramSchedule:TrailerLeadDays` läuft; ein Trailer-Clip-Sendeplatz zeigt seinen Film in der Programmauskunft. Regeln ohne Clip-Gruppe verhalten sich exakt wie bisher. Backups älterer Versionen bleiben wiederherstellbar: Die neuen Tabellen und die Spalte sind beim Restore optional, und eine fehlende `PlaceholderGrace`-Spalte wird mit dem 15-Minuten-Standard ergänzt. Siehe `docs/help/tv-sender.md`.
- Robustheitskorrektur mit Datenbereinigung: Die `Setups`-Einstellungszeile konnte durch einen Wettlauf beim Start doppelt entstehen (Daten-Upgrade, erster Request und Test-Seeds erzeugten sie jeweils per Check-then-Act nach leerem Lesen), und `FirstOrDefault` las dann wechselweise eine der beiden Zeilen — Schalter wie `TvSenderEnabled` konnten dadurch zwischen Anfragen kippen. Die Migration `AddSetupsSingleRowIndex` (wird automatisch angewendet) führt doppelte Zeilen zusammen — die älteste bleibt — und erzwingt die Ein-Zeilen-Invariante per Unique-Index über einen konstanten Ausdruck auf Datenbankebene; die Erzeugung läuft jetzt über einen einzigen geordneten Pfad, und ein unterlegener Insert liest die Gewinner-Zeile nach. Kein Handlungsbedarf; trug eine Datenbank je zwei abweichende Zeilen, gelten die Einstellungen der älteren Zeile.
- TV-Sender-Freischaltung: Der automatisierte TV-Sender ist jetzt standardmäßig ausgeschaltet und muss von einem Administrator über „Einrichtung → Allgemein → Automatisierten TV-Sender freischalten" ausdrücklich freigegeben werden (neue Spalte `Setups.TvSenderEnabled`, Migration `AddSetupTvSenderEnabled`, wird automatisch angewendet; beim Restore Standard `false`). Solange nicht freigegeben, ist der „Live-TV"-Navigationseintrag ausgeblendet, `/live-tv` und `/admin/tv-sender` zeigen einen Hinweis, `/api/program-guide/*` und `/api/live-stream/*` antworten 404, und die Sendeplan-/Segmentierungs-/Laufzeit-Worker ruhen. **Update-Hinweis:** Bestandsinstallationen behalten den Sender *deaktiviert*, bis er freigegeben wird — einmalig unter „Allgemein" aktivieren. Ebenfalls in dieser Änderung: Die Strangreihenfolge von Genre-Regeln ist jetzt ein deterministischer Hash-Mix je Regel statt alphabetisch (keine permanente „A"-Serie mehr vorn), und die Live-TV-Liste „Die nächsten Stunden" aktualisiert sich weiter, auch wenn der now/next-Endpunkt ausfällt (der Poll startet erst auf der interaktiven Instanz — kein Prerender-Timer-Leck). Siehe `docs/help/tv-sender.md`.
- TV-Sender-Regelfunktionen: Genre-Regeln mit mehreren Serien verschachteln die Sendungen jetzt innerhalb ihres Fensters, statt pro Tag eine Serie herauszustreichen — jede Sendung behält ihre Slot-Position über Tage hinweg und setzt ihre eigene Episodenreihenfolge mit einem eigenen persistierten Fortsetzungscursor je Serie fort (neue nullable Spalte `ProgramRuleCursors.StrandKey`, Migration `AddProgramRuleCursorStrandKey`, wird automatisch angewendet; Backups älterer Versionen bleiben wiederherstellbar, weil die Spalte beim Restore optional ist und zu `null` = ein Regel-Cursor wie bisher restauriert). Zwei neue Wiederholungsmodi kommen in den Regel-Editor — „Werktags (Mo–Fr)" und „Wochenende (Sa+So)" — und der Regel-Editor öffnet wieder als Overlay-Panel über der Regelliste, über den abgedunkelten Hintergrund schließbar wie die anderen Dialoge. Siehe `docs/help/tv-sender.md`.
- Der automatisierte TV-Sender erkennt jetzt Trailer-Dateien beim Medienscan nach der Plex/Jellyfin-Konvention — eine Datei mit `-trailer`-Suffix neben dem Film (`Film.mp4` → `Film-trailer.mp4`) und jedes Video in einem `trailers/`-Unterordner eines Filmverzeichnisses. Erkannte Trailer werden ihrem Film zugeordnet (neue Spalte `MovieMediaItems.IsTrailer`, Migration `AddMovieMediaItemIsTrailer`, wird automatisch angewendet; Backups älterer Versionen bleiben wiederherstellbar, weil die Spalte beim Restore optional ist und zu `false` restauriert), bekommen ihre Laufzeit wie jedes andere Video ermittelt und erscheinen nie als regulärer Film im Programm oder den Medienansichten. Ein neues Material „Trailer anstehender Filme" für Füller-Regeln lässt den Sendeplan Trailer bevorzugen, deren Film innerhalb des konfigurierbaren Vorlaufs `ProgramSchedule:TrailerLeadDays` (Standard: 7 Tage) läuft; wo kein passender Trailer existiert, decken die übrigen Füller-Regeln die Lücke wie bisher. In der Programmauskunft zeigt ein Trailer-Sendeplatz den Namen seines Films. Siehe `docs/help/tv-sender.md`.
- Die UDP-Broadcast-Discovery-Antwort (`VIDEOWEBPLAYER_SERVER:<url>` auf Port 5001) meldet jetzt die erreichbare öffentliche Basis-URL des Servers **vollständig inklusive Schema, Host, Port und Pfad** (z. B. `https://videos.example.com/videoplayer/`) statt des bisher fest gebauten `http://{Host:Address ?? "localhost"}:{Host:Port ?? "5000"}` — im Standard wird also nicht mehr die für Clients unbrauchbare `localhost`-Adresse gemeldet, sondern die LAN-IPv4 des Hosts mit dem gebundenen Port abgeleitet; Clients, die die Antwort auswerten, müssen einen Pfadanteil tolerieren (die Anpassung der MAUI-App ist eine Folgeaufgabe im App-Repository). Die gemeldete URL wird pro Anfrage in dieser Reihenfolge aufgelöst: neues Admin-Feld „Öffentliche Basis-URL" unter `Einrichtung` → `Allgemein` (persistiert in der neuen, nullable `Setups.DiscoveryPublicBaseUrl`-Spalte, die beim Start per Migration `AddSetupDiscoveryPublicBaseUrl` automatisch angelegt wird; Backups älterer Versionen bleiben wiederherstellbar, weil die Spalte beim Restore optional ist) → neue optionale Konfiguration `Discovery:PublicBaseUrl` (über `AutoUpdate:ProtectedFiles` merge-geschützt; ein ungültiger Wert lässt den Start fehlschlagen) → automatische Ableitung aus gebundenen Adressen, `Kestrel:Endpoints`, `Host:Address`/`Host:Port` und der LAN-Adresse des Hosts — Loopback-/Wildcard-Adressen werden nie gemeldet, ein loopback-artiges `Host:Address` wird jetzt ignoriert statt gemeldet. Unter IIS `OutOfProcess`, hinter einem Reverse-Proxy oder bei TLS-Terminierung sieht die Ableitung nur das interne Backend — dort ist eine explizite URL (Admin-Feld oder `Discovery:PublicBaseUrl`) Pflicht.
- Der Server kündigt sich jetzt selbst per mDNS/DNS-SD an (Diensttyp `_videowebplayer._tcp.local.`, UDP-Port 5353), damit Client-Apps ihn automatisch finden. In `appsettings.json` wurde ein neuer optionaler Abschnitt `Mdns` ergänzt (`Enabled`, `InstanceName`, `ServiceType`, `Port` — alle Schlüssel sind über `AutoUpdate:ProtectedFiles` merge-geschützt, lokale Anpassungen überstehen Updates). Das Advertisement ist nur aktiv, wenn sowohl `Mdns:Enabled` (Standard `true`, Betreiber-Master-Switch) als auch der neue Admin-Schalter „Server per mDNS im Netzwerk ankündigen" unter `Einrichtung` → `Allgemein` (standardmäßig an) gesetzt sind. Firewall: UDP 5353 muss offen sein (Multicast 224.0.0.251). Unter IIS `OutOfProcess` ist die gebundene Adresse der interne Backend-Port — dort `Mdns:Port` auf den Site-Port setzen. Auf einem Linux-Host, der den Server bereits über eine statische Avahi-Dienstdatei bekannt macht (`docs/INSTALL_AVAHI.md`), diese Datei entfernen oder `Mdns:Enabled=false` setzen, um Doppel-Advertisement zu vermeiden. Der UDP-Broadcast-Fallback auf Port 5001 bleibt unverändert. **Breaking für Discovery-Clients:** Clients und Integrationen, die den Server bisher unter `_http._tcp.local.` gesucht haben, müssen auf `_videowebplayer._tcp.local.` umstellen — der Server kündigt sich bewusst nicht parallel unter dem generischen Typ an (der Diensttyp selbst ist über `Mdns:ServiceType` konfigurierbar). Die MAUI-App wird im App-Repository auf den dedizierten Diensttyp umgestellt; bis dahin findet sie den Server über den UDP-Fallback.
- Update-Installationen unter IIS laufen jetzt ohne erhöhte Rechte: Der Updater erkennt das IIS-Hosting-Modell selbst (Out-of-Process und In-Process), legt die Site per `app_offline.htm` still, tauscht die Dateien und überlässt den Neustart IIS beim nächsten Request — es ist keine Konfiguration nötig. Ein konfigurierter `AutoUpdate:ServiceName`/`AutoUpdate:ExecutablePath` wird unter IIS ignoriert (mit Warnung im Log); das Dienstname-Feld in den Update-Einstellungen ist unter IIS gesperrt und ein persistierter Wert wird bereinigt. `AutoUpdate:AppPoolName`/`SiteName` nur setzen, wenn bewusst die privilegierte Variante gewünscht ist (erfordert IIS-Verwaltungsrechte der Pool-Identität). Hinweis für In-Process-Hosting: Das Update beendet den `w3wp` des Pools und setzt deshalb einen dedizierten Anwendungspool je Anwendung voraus. Diagnose: Alle Windows-Installationsskripte protokollieren jeden Schritt in `Updates/update.log` und legen im Fehlerfall eine Kopie des ausgeführten Skripts als `update-failed.ps1` ab; die Skripte laufen als entkoppelter Prozess (WMI `Win32_Process.Create`) — darf die Anwendungs-Identität `Create` in einer gehärteten Umgebung nicht ausführen, schlägt die Installation mit `InstallationFailed` fehl statt still zu scheitern. Siehe [martin-stromberg/msTools.Updater#69](https://github.com/martin-stromberg/msTools.Updater/issues/69) und [#70](https://github.com/martin-stromberg/msTools.Updater/issues/70).
- Behoben: Update-Installationen ersetzen deployment-seitige Dateianpassungen nicht mehr blind. Die ausgelieferte `AutoUpdate:ProtectedFiles`-Schutzliste schützt `web.config` und `appsettings*.json`: Das generierte Installationsskript sichert die Trefferdateien vor dem Paketkopiervorgang unter `Updates/backup/` und übernimmt danach die konfigurierten XML-Elemente/-Attribute (`<environmentVariables>`, `security/ipSecurity`, `httpProtocol`, deployment-eigene `aspNetCore`-Attribute) sowie aufgezählte JSON-Schlüssel aus der Bestandsdatei in die Paketversion — Paket-Verbesserungen derselben Dateien kommen weiterhin an. **Migrationshinweis:** Der Schutz greift erst ab dem ersten Update **nach** dieser Version, weil das Update auf diese Version noch mit dem Skript der alten Version läuft — Bestandsinstallationen tragen ihre `web.config`-/`appsettings`-Anpassungen einmalig nach dem Update auf diese Version nach. Unter Linux benötigt die `Merge`-Strategie `python3` auf dem Zielsystem (sonst werden Merges mit Logeintrag übersprungen; die Dateisicherungen bleiben unter `Updates/backup/`). - Laufzeitermittlung für entfernte Quellen jetzt über den eigenen internen HTTP-Stream-Endpunkt: Statt auf ffmpegs libssh zu setzen, bekommt ffprobe für jede nicht-lokale Datei eine Loopback-URL (`http://127.0.0.1:{port}/api/internal/media-stream/{token}`), über die es mit HTTP-Range-Requests seeken kann — es liest nur die Container-Metadaten (Sekunden statt der ganzen Datei) und greift dabei über denselben Quell-Lesepfad zu wie die Wiedergabe (z. B. SSH.NET bei SFTP), also quelltyp-unabhängig und ohne die in der Praxis auf manchen Servern beim Handshake abgelehnten libssh-Builds. Der Zugriff ist an ein kurzlebiges, zufälliges Stream-Token gebunden (nur diese eine Datei, nur im Arbeitsspeicher, Lebensdauer `MediaProbe:HttpProbeTokenLifetimeSeconds`, Standard 600 s) — kein Benutzerkonto und kein langlebiges Geheimnis in der Kommandozeile. Die Loopback-Adresse wird aus den gebundenen Server-Adressen ermittelt (`MediaProbe:HttpProbeBaseUrl` setzt sie bei Bedarf, `MediaProbe:HttpProbeEnabled` schaltet den Pfad ab; HTTPS-only-Installationen fallen automatisch zurück). Die Fallback-Kette je Versuch ist nun HTTP-Probe → `sftp://` (bleibt für kompatible Server erhalten) → gestreamtes `pipe:0`; HTTP-Transportfehler (unerreichbarer/ablehnender Endpunkt) werden erkannt und lösen den nächsten Pfad aus, echte Dateifehler bleiben dauerhaft. Siehe `docs/help/videolaufzeit.md`.

- Einlesen, Klassifizierung (NFO-Metadaten, Cover- und Schauspielerbilder) und Streaming/Downloads funktionieren für lokale Quellen genauso wie für SFTP-Quellen; versteckte Einträge (Namen mit führendem `.`) werden übersprungen.
- Backups aus älteren Versionen können weiterhin wiederhergestellt werden: Eine fehlende `SourceType`-Spalte in `MediaSources` wird mit dem Standard `SFTP` ergänzt.
- Behoben: Das Navigationsmenü ruft die Medienquellenliste nur noch für angemeldete Benutzer mit gültigem Autorisierungstoken ab.
- Neue Hilfeseiten zu Medienquellen unter `docs/help/medienquellen/`.
- Das Backup-Upload-Limit lässt sich in den Einstellungen jetzt als Wert mit Einheit (MB/GB) statt in Bytes eintragen.
- Der Backup-Upload überträgt Dateien jetzt in Abschnitten (Chunks) als `application/octet-stream` und unterstützt Backups über 6 GB.
- Unterbrochene Uploads können an der bereits übertragenen Position fortgesetzt werden — auch nach einem Seitenreload oder einer unterbrochenen Verbindung; nicht abgeschlossene Uploads werden mit Dateinamen angezeigt und können verworfen werden.
- Fortschrittsanzeige mit übertragener/Gesamtgröße und Prozentangabe, automatische Wiederholung bei Netzwerkunterbrechungen und verständliche Fehlermeldungen bei endgültigem Fehlschlag.
- Nicht abgeschlossene Uploads, auf die länger als 24 Stunden nicht zugegriffen wurde, werden automatisch aufgeräumt.
- Eine bereits vorhandene gleichnamige `.bak`-Datei wird beim Import jetzt ersetzt.
