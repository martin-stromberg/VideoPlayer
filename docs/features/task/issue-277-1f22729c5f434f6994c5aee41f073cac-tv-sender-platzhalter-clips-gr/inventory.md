# Bestandsaufnahme: Platzhalter-Clip-Gruppen mit karenzzeitgesteuerter Lückenfüllung im Sendeplatz (Issue #277, Nachbesserung zu Issue #111)

Analyse des bestehenden Projektstandes (ASP.NET Core + Blazor, Projekte `VideoWebPlayer/`, `VideoWebPlayer.Client/`, `VideoWebPlayer.Tests/`) bezogen auf die übersetzte Anforderung in [requirement.md](requirement.md). Einstiegspunkt war die ältere Bestandsaufnahme von Issue #111 (`docs/projects/task/issue-111-6145c51699f34953bf29a244634a23e2-automatisierter-tvsender/inventory*`); alle dortigen Befunde wurden gegen den aktuellen Code verifiziert — der TV-Sender ist inzwischen vollständig implementiert.

## Zusammenfassung

- **Die Clip-Gruppen-Funktion existiert noch nicht.** Keine Entities `ProgramClipGroup`/`ProgramClipGroupItem`/`ProgramRuleClipGroup`, keine Karenzzeit an `ProgramRule`, kein Gruppen-Service, keine UI für Gruppen, keine entsprechenden Tests (Volltextsuche `ClipGroup`/`PlaceholderGrace`/`Karenz` über alle Projekte ohne Treffer).
- **Die Anknüpfungspunkte existieren und sind verifiziert:**
  - `ProgramRule` besitzt `SlotDuration` (zeitbasierte Periode), `MaterialType`/`MaterialId` (polymorphe Materialreferenz) und die Join-Collections `Genres`/`MediaSourceFilters` — `ProgramRuleGenre`/`ProgramRuleMediaSource` mit Composite-PK und Kaskaden sind das vorhandene Join-Muster für eine Gruppe↔Regel-Zuordnung.
  - `MediaItem.Duration`/`DurationProbedAt`/`DurationProbeAttempts` existieren („bekannte Abspiellänge"); die Clip-Kandidatenmenge „unklassifizierte Video-`MediaItem`s" ist in `ProgramScheduleService.ExpandMediaSourceClipsAsync` implementiert (`MediaSourceClips`-Material, `FillGaps`-Nutzung bleibt davon unberührt).
  - Die reservierte „Trailer"-Gruppe kann auf den vorhandenen Mechanismen aufsetzen: `ProgramRuleMaterialType.Trailer`, `ExpandTrailersAsync`, `ExpandTrailerStatesAsync` (verzögerte Expansion nach der Materialisierung), `FindLeadMatchOffset`, `LoadMovieAiringsAsync`/`BuildMovieAiringsFromSlotsAsync`, `TrailerMediaItemIdsAsync`, `ProgramScheduleOptions.TrailerLeadDays` (Default 7, einziger gesetzter Wert in `appsettings.json`).
  - Die Startschwelle ist global: `_minStartRemain` aus `ProgramSchedule:MinStartRemainSeconds` (Default 30 s), ausgewertet in `SelectAiringItems`/`SelectAiringItemsInterleaved` — eine je-Regel-Karenzzeit existiert nicht.
  - `FillGaps` füllt nur Lücken **zwischen** Ausstrahlungen über `Filler`-Regeln; eine Füllung **innerhalb** der Regel-Periode mit Clip-Slots gibt es nicht. `SummaryCounters.RemainingGapSeconds` dokumentiert Restlücken bereits.
  - `ProgramSlot` trägt `RuleType`-Snapshot + weiche `ProgramRuleId`; Clip-Slots wären fachlich über `MovieId == null && TVShowEpisodeId == null` erkennbar. Die Reproduzierbarkeitsprüfung (`AiringReproducible`/`FlatAiringTailReproducible`/`InterleavedAiringTailReproducible` über `ReconcileWindow`) vergleicht Slot-Folgen slotweise gegen `SelectAiringItems` — eingestreute Clip-Slots müssten dort abgebildet oder erkannt werden.
  - `ProgramRuleCursor` + `ProgramCursorContentType` (`Trailer`, `MediaItem` vorhanden) decken einen persistierten Clip-Fortschritt ab.
  - `ProgramRuleService`/`ProgramRuleInput`/`ValidateRuleInputAsync`/`ReplaceGenreLinksAsync` + `RequireAdminAsync` sind die bestehenden Stellen für Gruppen-Ids, Karenzzeit und die serverseitige „Trailer"-Namensreservierung (Letztere existiert noch nicht).
  - `TVSenderAdmin.razor`: Regel-Dialog mit Mehrfachauswahl-Mustern (`rule-material-genre`, `rule-material-sources`), Minuten-Eingabe (`rule-duration`), `MaterialLabel`; `ProgramGuideService.LoadDetailsAsync`/`ToEntry` und `SlotCard` besitzen bereits den `MediaItem.Name`-Fallback für Clip-Slots.
  - Backup: `VideoWebPlayerBackupData` mit `OptionalRestoreTables`/`OptionalRestoreColumns`; Default-Listen nur für `bool`/`long`/`int` — **kein `TimeSpan`-Default** vorhanden; `LegacyBackupArchiveBuilder` + `VideoWebPlayerBackupDataTests_*` bilden den Alt-Backup-Regressionstest-Rahmen.
- **Test-Ausgangszustand:** Drei CI-Filter-Läufe in Release — `Category!=E2E`: 2.066/2.067 bestanden, 0 Fehler, 1 übersprungen (plattformbedingter Unix-Skip); `Category=Integration`: **0 Tests** (Kategorie existiert nicht); `Category=E2E`: 223/226 bestanden, **2 Fehlschläge** (`FfmpegLiveStreamSegmenterE2ETests.SecondJob_PlaylistContinuesAndMarksDiscontinuity`, `BackupUploadE2ETests.BackupUpload_NavigatingAwayDuringUpload_AbortsWithoutRedirectBack` — beide in Einzelwiederholung bestanden, als Flakes dokumentiert), 1 übersprungen (dokumentierter `[Fact(Skip)]`-Befund). Auffälligkeit: drei Playwright-E2E-Klassen (`TVSenderAdminE2ETests`, `TVSenderAdminE2ETests_FfmpegDownload`, `LiveTvE2ETests`) tragen kein `Category=E2E`-Trait und laufen im Nicht-E2E-Filter mit. Nachweis: [inventory/tests.md](inventory/tests.md), Reports unter [inventory/test-results/](inventory/test-results/).
