## Fehlende oder unvollständige Testanforderungen

- [ ] Kein Test für ein **mehrteiliges** >24-h-Airing (Kette normaler Items/Episoden statt Einzel-Langslot — der im Requirement ausdrücklich genannte „Marathon-/Special-Block"). Alle geplanten Tests bauen auf einem einzelnen >24-h-Item auf bzw. lassen die Kettenform offen; damit wird Lücke A (Auslöser auf Slot-Ebene) nicht abgesichert (AC1, AC3).
- [ ] Kein Test bzw. keine Festlegung zum Verhalten bei **verschmolzenen Airing-Ketten** (Airing-Dauer ≥ Wiederholungsintervall, z. B. tägliche Regel): Die geplanten Kern-Tests erzeugen selbst solche Ketten und erwarten `SlotsDisplaced == 0` — ohne dass der Plan einen Mechanismus beschreibt, wie eine Multi-Occurrence-Gruppe die `expected.Count - k == airing.Count`-Prüfung (Z. 524 / 667) bestehen soll (AC1).

## Fehlende oder unvollständige Planbestandteile

- [ ] **Auslöser des Zwei-Phasen-Ladens auf Airing-Gruppen-Ebene statt Slot-Ebene:** `Start < loadFrom && End > coverageStart` auf einem einzelnen Slot erkennt nur >24-h-Einzel-Slots, die noch laufen. Für mehrteilige >24-h-Airings (Kopf der Gruppe vor `loadFrom`, Gruppe reicht über `coverageStart` hinaus) feuert der Auslöser nie → erweiterter Lookback greift nicht (AC1, AC3, AC4). Eine Gruppierung vor der Auslöserprüfung oder ein Kriterium wie `scheduled.Any(s => s.Start < loadFrom)` ist nicht beschrieben.
- [ ] **Umgang mit verschmolzenen Airing-Ketten fehlt:** Für Airings ≥ Wiederholungsintervall (genau der Bug-Fall unter täglichen/dichten Regeln) erzeugen `ShiftPastInvaders`-Kontiguität und Lookback-Konsumation eine lückenlose Same-Rule-Kette, die `GroupAirings` zu einer Gruppe verschmilzt. `AiringReproducible`/`AiringReproducibleInterleaved` — vom Plan bewusst unverändert gelassen — können eine Multi-Occurrence-Gruppe prinzipiell nicht reproduzieren (Zählvergleich Z. 524/667; Rückwärtslauf bildet nur Präfix-Items einer einzigen Occurrence ab). Der Plan benennt das Risiko nur als „im Regressionslauf zu beobachten", erkennt aber nicht, dass sein eigenes Kern-Szenario (tägliche Regel + >24-h-Item, Vortags-Occurrence im Lookback) zwangsläufig eine solche Kette erzeugt und AC1 damit ungelöst bleibt. Es fehlt eine Entscheidung/Mechanismus (z. B. Gruppenbildung an Occurrence-Grenzen, Mehr-Occurrence-Hypothese oder bewusst eingeschränkter Geltungsbereich mit Test-Setup ohne Verschmelzung — z. B. `Recurrence.Once`/wöchentliche Regel — samt ehrlicher Dokumentation der Grenze).
- [ ] Randfall im Auslöser: Slot-Grenze exakt auf `loadFrom` (End == loadFrom wird wegen `End > loadFrom` nicht geladen; Start == loadFrom erfüllt `Start < loadFrom` nicht) — eine Kette, deren Slot genau an der Fenstergrenze beginnt, bleibt auch bei korrigierter Bedingung unentdeckt; die Ungleichheitssemantik ist im Plan nicht durchdacht.
