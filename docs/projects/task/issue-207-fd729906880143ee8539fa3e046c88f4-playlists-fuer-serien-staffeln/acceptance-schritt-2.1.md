# Abnahmeprüfung – Entwicklungsschritt 2

## Ergebnis

**Status:** Abweichungen gefunden

## Abweichungen

- [ ] **Kein Hinweis an den Anwender bei übersprungenen Duplikaten.** Die Anforderung verlangt: „Beim Hinzufügen bereits enthaltener Titel werden diese übersprungen und der Anwender erhält einen entsprechenden Hinweis." Der Code trennt beide Fälle und erfüllt in keinem beide Hälften der Regel:
  - *Kaskadenfall (übersprungen, aber kein Hinweis):* In `VideoWebPlayer/Services/PlaylistService.cs` (`AddMediaToPlaylistAsync`) werden bereits vorhandene Kind-Einträge über `newCascadeEntries = cascadeEntries.Where(e => !existingKeys.Contains(e))` still herausgefiltert. Die Rückgabe ist ausschließlich der Top-Level-Eintrag (`ToDto(topLevelEntry, mediaTitle, null)`); weder `DtoPlaylistEntry` (`VideoWebPlayer.Client/Models/DtoPlaylistEntry.cs`) noch die API-Antwort transportieren eine Anzahl oder Liste übersprungener Titel. In `VideoWebPlayer/Components/Playlists/PlaylistDetail.razor` setzt `AddEntryAsync` im Erfolgsfall gar keine Meldung (`entriesStatusMessage` wird nur zurückgesetzt). Beispiel: Episode 5 einzeln hinzufügen, danach die Staffel hinzufügen → Episode 5 wird übersprungen, der Anwender sieht keinerlei Hinweis. Die eigene Dokumentation hält das als bewusste Entscheidung fest und widerspricht damit der Anforderung (`docs/help/playlists-business-rules.md`: „Still übersprungen … Benutzer sieht nur: ‚Serie A wurde hinzugefügt' (keine Details über übersprungene Duplikate)"; `docs/help/playlists-api.md`: „Cascade-Duplikate werden still übersprungen").
  - *Top-Level-Fall (Hinweis, aber nicht übersprungen):* Ist der hinzugefügte Titel selbst bereits enthalten, wird die gesamte Operation mit `InvalidOperationException("Medieninhalt bereits in dieser Playlist vorhanden.")` abgebrochen und als HTTP 409 gemeldet, statt den Titel zu überspringen. Folge: Wird eine bereits enthaltene Serie erneut hinzugefügt (etwa um zwischenzeitlich erschienene Episoden nachzuziehen), scheitert der Aufruf komplett; es wird nichts hinzugefügt.

- [ ] **Eindeutigkeit eines Titels je Playlist ist über die API umgehbar (Groß-/Kleinschreibung des Medientyps).** Die Anforderung verlangt: „Ein und derselbe Titel darf innerhalb einer Playlist nur einmal vorkommen." In `PlaylistService.AddMediaToPlaylistAsync` wird der Medientyp zwar über `ParseMediaType` mit `ignoreCase: true` validiert, gespeichert wird aber der **rohe** Request-String (`MediaType = mediaType`, nicht `parsedMediaType.ToString()`). Die Duplikatsprüfung `existingKeys.Contains((mediaType, mediaId))` vergleicht ordinal, und der Unique-Index `HasIndex(e => new { e.PlaylistId, e.MediaType, e.MediaId })` (`VideoWebPlayer/Data/Configurations/PlaylistEntryConfiguration.cs`) greift auf SQLite mit BINARY-Kollation ebenfalls case-sensitiv. Zwei Aufrufe mit `mediaType` = `"Movie"` und `"movie"` und derselben `MediaId` legen daher zwei Einträge für denselben Film an; beide werden anschließend angezeigt, da `GetMediaTitlesAsync` den Typ wieder case-insensitiv auflöst. Über die UI ist das nicht erreichbar (dort werden nur die Konstanten aus `MediaTypeValues` gesendet), über die dokumentierte REST-Schnittstelle (`docs/API.md`, `docs/help/playlists-api.md`) jedoch schon.

## Hinweise

Die übrigen geprüften Punkte sind erfüllt:

- **Kaskadierende Auflösung** ist vollständig und korrekt umgesetzt (`MediaTypeHandlers` in `PlaylistService.cs`): `TVShow` → alle Staffeln (`TVShowSeason.TVShowId`) **und** alle deren Episoden; `TVShowSeason` → alle Episoden (`TVShowEpisode.TVShowSeasonId`); `MovieCollection` → alle Filme (`Movie.MovieCollectionId`). `Movie` und `TVShowEpisode` haben bewusst keinen Kaskaden-Handler. Belegt durch `PlaylistServiceTests_AddMedia.AddMedia_TVShow_CascadesEpisodes`, `AddMedia_TVShowSeason_CascadesEpisodes`, `AddMedia_MovieCollection_CascadesMovies` und den E2E-Test `PlaylistEntriesE2ETests.AddTVShow_CascadesSeasonsAndEpisodes`.
- **Ursprung des Sammel-Eintrags** wird pro Titel persistiert: `PlaylistEntry.ParentMediaType` / `ParentMediaId` (Migration `20260905165237_AddPlaylistEntriesTable`), gesetzt auf den ursprünglich hinzugefügten Sammel-Eintrag, `null` beim Top-Level-Eintrag. Beim Hinzufügen einer Serie tragen auch die Episoden die Serie (nicht die Staffel) als Ursprung — für die spätere Zuordnung neu erscheinender Inhalte ist das tragfähig.
- **Entfernen** löscht ausschließlich die eine `PlaylistEntry`-Zeile (`RemoveMediaFromPlaylistAsync`), gefiltert über `PlaylistId`. Weder der Medientitel selbst noch Einträge anderer Playlists werden berührt; es gibt keinerlei Kaskade auf die Medientabellen.
- **Zugriffsschutz**: Alle fünf Entry-Endpunkte laufen über `GetOwnedPlaylistAsync`, das bei fremdem `UserId` eine `PlaylistAccessDeniedException` wirft; der Controller (`[BearerTokenCheck]`, `CheckLogedIn()`) mappt sie auf HTTP 403, fehlende Anmeldung auf 401. Abgedeckt durch `AddMedia_NotOwner_*`, `RemoveMedia_NotOwner_*`, die Controller-Tests und den E2E-Test `AddMovie_ForeignPlaylist_ShowsErrorMessage`.
- **Beliebige Kombinationen** aller fünf Typen sind möglich: Der Schlüssel ist `(PlaylistId, MediaType, MediaId)`, es gibt keine typbezogene Einschränkung. `ParseMediaType` lässt ausschließlich die fünf definierten Typen zu (`AddMedia_InvalidMediaType_ThrowsInvalidOperationException`).
- **Optionales Maximum**: `PlaylistSettings.MaxPlaylistItemCount` ist konfigurierbar, in `appsettings.json` auf `null` (deaktiviert) gesetzt und zählt Kaskaden-Einträge mit; bei Überschreitung wird ohne Teil-Insert abgebrochen.
- **Verwaiste Einträge** werden in `GetPlaylistEntriesAsync` still entfernt (`RemoveRange(orphans)`), passend zur Vorgehensentscheidung.
- Das Fehlen einer sortierten Infinity-List-Darstellung ist laut Vorgehensentscheidung ausdrücklich keine Abweichung; die vorhandene Tabelle in `PlaylistDetail.razor` genügt für Schritt 2.
- Weitere Beobachtung (keine Anforderungsabweichung): Wird der Top-Level-Sammel-Eintrag (z. B. die Serie) entfernt, bleiben dessen Kind-Einträge mit einem `ParentMediaId` zurück, das auf keinen Playlist-Eintrag mehr zeigt. Für die Anzeige ist das unkritisch (`ParentMediaTitle` wird weiterhin aus dem Medienbestand aufgelöst), sollte aber bei der Nachzugs-Logik in Folgeschritten berücksichtigt werden.
